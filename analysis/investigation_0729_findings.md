# 7/29 データ未受信調査結果

## 根本原因

**KABUステーションのWebSocket PUSH配信が7/29は終日完全に停止していた。**

### 証拠（kabu_relay.logの7/29セクション: line 106302-113338）

1. **WS受信=0件/分が全日続いた**（400分間すべて0件）
2. **自動復旧が154回トリガーされた**（5分ごとにWS再起動を繰り返したが回復せず）
3. **RESTフォールバック=14件/分**が安定して続いた（14銘柄のみ）

### なぜ6銘柄だけ欠落したか

WS PUSH配信が死んでいたため、全銘柄がRESTフォールバック（`GET /board/{symbol}@1`）に依存。

RESTフォールバックの送信条件:
```python
board_raw = fetch_board_from_api(symbol, token)
if board_raw and board_raw.get("currentPrice", 0) > 0:
    # → 送信
else:
    continue  # → スキップ
```

6銘柄（285A, 6526, 6976, 3436, 3778, 5016）は:
- REST APIは200を返した（板情報取得スキップは初回の1-2回のみ）
- しかし `currentPrice = 0` だったため、candle生成がスキップされた

### なぜcurrentPrice=0だったか

KABUステーションのREST API `/board/{symbol}@1` は:
- 銘柄が**PUSH配信登録されていない**場合、currentPrice=nullまたは0を返す
- PUT /register は200を返したが、**内部的に6銘柄の登録が有効にならなかった**

### 7/28との比較

- 7/28: WS蓄積使用=20件/分（正常、全20銘柄がWSティック受信）
- 7/29: WS蓄積使用=0件/分（完全停止）、RESTフォールバック=14件/分

### 未受信6銘柄と受信14銘柄

**未受信（REST APIでcurrentPrice=0）:**
- 285A（キオクシアHD）
- 6526（ソシオネクスト）
- 6976（太陽誘電）
- 3436（SUMCO）
- 3778（さくらインターネット）
- 5016（JX金属）

**受信（REST APIでcurrentPrice>0）:**
- 8035, 6857, 6920, 9107, 8306, 9984, 7011, 4568, 6981, 5803, 8316, 6758, 6723, 7203

### 推定される根本原因

KABUステーションの内部状態に問題があり:
1. WebSocket PUSH配信が全銘柄で停止（接続は確立するがデータが来ない）
2. REST API `/board` は一部銘柄のみ有効（14銘柄はcurrentPrice返却、6銘柄は0）
3. PUT /register は200を返すが実際には一部銘柄の登録が無効

### 対策案

1. **KABUステーションの完全再起動**（アプリケーション終了→再起動）
2. スクリプト側: REST APIでcurrentPrice=0が続く銘柄を検知してアラートを出す
3. スクリプト側: WS受信=0が一定時間続いた場合、KABUステーション再起動を促す通知
