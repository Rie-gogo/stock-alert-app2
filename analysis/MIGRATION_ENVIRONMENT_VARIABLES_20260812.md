# stock-alert-app 移行用環境変数一覧

作成日: 2026-08-12（日本時間）

この文書は、新サーバーへの移行AIに渡すための**変数名・用途・置換方針だけ**をまとめたものです。実際の秘密値（パスワード、トークン、接続文字列）は記載していません。

> 重要: 秘密値をGitHub、バックアップZIP、チャット、ソースコードへ書き込まないでください。移行先のシークレット管理（環境変数、Secret Manager、Vault等）で新規に設定します。

## 1. 移行先で必須の環境変数

| 変数名 | 現行での用途 | 移行先の対応 |
|---|---|---|
| `DATABASE_URL` | MySQL/TiDBへの接続。1分足、取引履歴、日次集計、注文指示等の全DBデータを使用 | **必須**。新DB用の接続文字列を設定。SQLバックアップを復元したDBを指定する |
| `JWT_SECRET` | WebアプリのセッションCookie署名 | **必須**。移行先でランダムな十分長い値を新規発行する。旧値のコピーは不要 |
| `NODE_ENV` | 本番／開発モードの切替 | 本番では `production` |
| `PORT` | Expressサーバーの待受ポート | 移行先ホスティングの指定に従う。PaaSが自動指定する場合は設定しない |

## 2. 認証に関する変数（Manus OAuth依存）

| 変数名 | 現行での用途 | 移行先の方針 |
|---|---|---|
| `VITE_APP_ID` | Manus OAuthアプリ識別子 | Manus外へ移す場合は**使用しない**。移行AIが新しい認証方式（単一管理者ログイン、Auth0、Google OAuth等）へ置換する |
| `OAUTH_SERVER_URL` | Manus OAuthサーバーURL | Manus外では**使用しない**。新しい認証サーバー設定へ置換する |
| `VITE_OAUTH_PORTAL_URL` | フロントエンドのManusログイン遷移先 | Manus外では**使用しない**。新しいログイン画面・認証プロバイダURLへ置換する |
| `OWNER_OPEN_ID` | Manus所有者識別子 | Manus外では不要。新認証の管理者ロール／ユーザーIDへ置換する |

## 3. Manus組込みサービスに関する変数

| 変数名 | 現行での用途 | 移行先の方針 |
|---|---|---|
| `BUILT_IN_FORGE_API_URL` | ManusのData API、ストレージ、通知、スケジュール等の組込みサービスのURL | Manus外では値をコピーしない。実際に使う機能だけ、外部API・S3・メール／通知・cronへ置換する |
| `BUILT_IN_FORGE_API_KEY` | 上記組込みサービスのサーバー側認証鍵。日次エンドポイントの保護にも使用 | Manus外では値をコピーしない。スケジュール呼出し用は新しい `SCHEDULE_SECRET` 等へ置換し、外部サービス用の鍵は各サービスで新規発行する |
| `VITE_FRONTEND_FORGE_API_URL` | `Map.tsx` のManus Mapsプロキシ | 地図機能を使わないなら不要。使う場合は移行先のMaps APIプロキシへ置換する |
| `VITE_FRONTEND_FORGE_API_KEY` | フロントエンドMapsプロキシの認証 | 地図機能を使わないなら不要。使う場合は新しい公開可能なMaps設定に置換する |

## 4. 分析・KABU関連の変数

| 変数名 | 現行での用途 | 移行先の方針 |
|---|---|---|
| `JQUANTS_API_KEY` | J-Quantsの過去データ取得、バックテスト、分析スクリプト | 過去データ分析を続ける場合のみ新サーバーのシークレットとして設定。リアルタイムKABU 1分足の受信だけなら必須ではない |
| `KABU_API_PASSWORD` | 共通環境定義にはあるが、現行のサーバー実運用コードでは直接参照されていない | 新サーバーには設定しない。KABUステーションのAPIパスワード／トークンはWindows PCのrelay側だけで扱う |

## 5. Manusが自動注入しているが、現行コードでは必須参照でない変数

以下は現行のManus環境に存在する可能性がありますが、移行先の動作要件としては、上記の必須・認証・組込みサービスの整理後に改めて判断します。

```text
OWNER_NAME
VITE_APP_TITLE
VITE_APP_LOGO
VITE_ANALYTICS_ENDPOINT
VITE_ANALYTICS_WEBSITE_ID
```

## 6. 移行AIに渡す実装指示

1. GitHubとDBバックアップを復元する。
2. `.env`をGit管理対象外にし、下記のテンプレートを基に移行先のシークレット管理で値を設定する。
3. Manus OAuthとForge APIをそのままコピーしない。新しい認証、スケジュール認証、外部サービスへ置換する。
4. Windows relayの`CLOUD_BASE_URL`を新しいHTTPS URLに変更する。
5. 移行後は`DRY_RUN=True`を維持し、1分足受信、DB書込み、シミュレーション、日次集計を確認してから実発注のテストを再開する。
